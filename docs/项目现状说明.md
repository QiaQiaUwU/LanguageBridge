# LanguageBridge 项目现状说明

这是当前唯一的项目说明文档（原来分散的 v2/v3 改造记录已合并到这里，避免多份文档互相矛盾）。

## 一、启动方式

双击项目根目录的 **`启动LanguageBridge.bat`**。会打开一个窗口，自动打开浏览器；**关闭这个窗口就是停止服务**，不需要去任务管理器找进程。

**打包成单个 .exe 发给别人用**（不用装 Node/npm）：在项目目录跑 `npm run build:exe`，会在 `dist-exe/` 目录生成 `LanguageBridge.exe` + `port.txt`，这两个文件拷给别人，对方电脑不需要装任何东西，双击 exe 就能跑起来（原理：用 `pkg` 把 Node 运行时和已经构建好的前端一起打包进一个文件）。这条打包链路我在沙盒里装了 Wine 模拟 Windows 环境实测过，exe 真的能启动、HTTP 服务真的能正常响应、局域网信息接口和 AI 转发接口也都验证过，不是"理论上应该行"。

有个已知限制说清楚：**exe 图标是系统默认的那个，没有做自定义**。试过用 `rcedit` 给打包出来的 exe 嵌入自定义图标，嵌入操作本身能成功，但改完的 exe 直接打不开、报"Pkg: Error reading from file"——查了一圈，这是 `pkg` 这个打包工具的生态里一个公开已知、长期没有官方修复的兼容性问题（不管用 rcedit 还是 Resource Hacker 改图标都会破坏 pkg 塞进 exe 里的那份数据，GitHub 上 `vercel/pkg` 的 #1109、#1894，`electron/rcedit` 的 #107 都是这个问题）。与其为了图标好看换来一个打不开的 exe，选择了保证能跑、图标朴素这条路。想要好看图标：在 Windows 上给这个 exe 建一个快捷方式，右键快捷方式→属性→更改图标——快捷方式的图标是独立存储的，不会碰 exe 本体，不会有这个问题。

**手机/平板连接**（参考 MyLibrary 的局域网二维码方案）：服务现在监听 `0.0.0.0`（之前只监听 `127.0.0.1`，只有这台电脑自己能访问），手机/平板连同一个 WiFi 就能直接访问。顶部导航栏点"手机连接"，会弹出局域网地址和二维码（用的跟你一样的 `api.qrserver.com` 免费生成，这一步需要联网；地址本身访问不需要联网，只是生成二维码图片这一下要）。如果这台电脑装了防火墙，首次连接可能会弹窗问"是否允许网络访问"，选允许就行。

**可以装到主屏幕（PWA）**：手机/电脑用浏览器打开之后，浏览器会提示"添加到主屏幕"/"安装应用"（Chrome/Edge 地址栏或菜单里也能手动装），装完之后图标会出现在主屏幕/桌面，打开是独立窗口，不带浏览器地址栏，跟原生 App 差不多。加了 `manifest.webmanifest` + `sw.js`（service worker），图标是新生成的（蓝底白字"LB"）。这个 service worker 故意写得很"薄"——只满足"能安装"这个硬性条件，不做离线缓存，因为你的构建产物每次文件名都带哈希，激进缓存反而可能导致更新代码之后浏览器还在用缓存的旧文件，这比装不上主屏幕更麻烦。

依赖安装和构建现在是**智能判断**，不是每次都无脑重来：
- 只有 `package-lock.json` 比上次装的时间新（比如我又加了新依赖）才会重新 `npm install`
- 只有 `apps/`、`shared/`、`src/` 等源码比上次构建结果新（比如换了新代码包）才会重新构建
- 都没变的情况下几乎是秒开，不会每次都做无谓的磁盘读写

**如果启动时报 `ENOSPC: no space left on device`**：这是磁盘空间不够了，不是代码问题。检查一下项目所在的盘（比如你的 F 盘）和 `C:\Users\你的用户名\AppData\Local\npm-cache` 所在的 C 盘还有没有空间，清理一下再试。如果 npm 缓存占用比较大，可以运行 `npm cache clean --force` 清一下缓存（缓存清空不影响项目本身，下次装依赖会重新下载）。

**做成桌面图标**（可选，Windows 自带功能，不用任何脚本，不会被杀毒软件误报）：
右键 `启动LanguageBridge.bat` → 发送到 → 桌面快捷方式。想换图标：右键桌面上的快捷方式 → 属性 → 更改图标 → 选择项目里的 `public/icon.ico`。

> 之前版本用 vbs 脚本自动创建桌面快捷方式，因为"用脚本创建桌面快捷方式"这个行为模式本身就是杀毒软件重点盯防的可疑特征（真实的"劫持主页"木马也常用同样手法），容易被误报为 `Trojan/VBS.StartPage`。现在换成上面这种 Windows 自带的手动创建方式，功能一样，但不会再被杀软拦截。

**换端口**：如果 58712 这个端口也和你别的项目冲突，改一下项目根目录的 `port.txt` 文件里的数字就行（改完保存，下次启动生效）。就算不改，程序自己发现端口被占用也会自动往后找一个空的端口用，日志里会告诉你实际用的是哪个端口。

**彻底停止 / 找不到进程时**：双击 `停止LanguageBridge.bat`，会按 `port.txt` 里的端口号自动找到对应进程并结束掉。

**命令行方式**（备用）：
```bash
npm install
npm run dev      # 开发模式 localhost:3000
npm run build    # 打包
npm run start    # 打包后用内置静态服务器启动（等同双击 bat 效果）
npm run type-check  # 类型检查
```

## 二、功能总览

### 词汇中心
- 卡片排版：加粗单词 + 音标 + 内联小喇叭 + 词性标签 + 释义遮挡线，例句 + 中文释义遮挡线，逐卡显隐
- 卡片网格宽度自适应，屏幕越宽列数越多（不再固定死 2 列），卡片间距更紧凑，每行仍然对齐整齐
- 每页数量可调（10/20/40/60，分页栏右侧选择）
- 顶部导航栏「词汇中心」左边是全局搜索框，输入即搜索单词/释义，非词汇中心页面输入会自动跳转过去
- 导入：支持 TXT / CSV / JSON / MD / DOCX / PDF，格式如 `word;中文`、`word；中文`、`word\t中文`、`word n. 中文`、CSV、JSON，词组安全，前置词性/音标自动抽取；**一个文件 = 一个词书**，重复单词自动归入词书不重复建条。DOCX/PDF 会先提取纯文本再按同样规则解析——PDF 如果是分栏或表格排版（比如听力同义替换、词汇手册这类），提取顺序可能会错乱，优先建议用 TXT
- **导入完整释义库**：一键把"英语词汇可视化学习系统"的全部词条导入成可浏览词书，按 高中/CET6/考研/托福/雅思 等分类自动拆成多个词书 + 一个全量词书（需要先关联释义库文件夹，不复制文件，见第三节）
- 标注：卡片悬浮出现「认识/模糊/不认识」三键（再点取消），顶部按状态筛选，持久化
- 卡片背单词：选范围（当前页/当前页及之后/全部）→ 全屏卡片，自动发音，翻面看释义，键盘 ←认识 ↑模糊 →不认识 ↓翻转
- 「听写」按钮选范围后进入听写页的设置界面（可再选拼写测试/朗读复习/听力材料三种模式），不再直接跳过设置
- 默认/乱一/乱二排序、学习模式/列表模式、全局遮住/显示释义
- 单词详情弹窗里的**同根词/近义词/反义词现在点击可以跳转**——如果那个词已经在库里（比如导入完整释义库之后基本都收录了），会直接打开它的详情；没收录会提示去 AI 助手查询。这几类相关词现在**都带发音按钮**了（之前近义词有但按钮显示的是">>"文字容易被当成跳转箭头看不出是发音，同根词/反义词/释义中的近义词之前压根没有发音按钮，这次一起补上，单个词用真人语音，短语用语音合成）
- 词条不再显示"英语词汇可视化学习系统"这个来源标签了（每个整库导入的词都一样的文案，没有区分度，纯属信息噪音；有区分度的来源比如你自己导入的词书名、"阅读：文章标题"这种还是会显示）
- **清理重复词条**：如果反复导入过释义库，同一个词可能因为历史版本的 bug 积累了好几份重复记录，现在有个"清理重复词条"按钮（导入区域下方），会自动识别同名词、保留信息最完整的那一份（有释义的优先、有音标例句的优先、已经标注过状态的优先），合并掉重复的，同时把词书里对重复词条的引用也一并修正
- **词书可以删除了**：每个词书 chip 右上角有个 ×，点了会二次确认，删除只是去掉这个分类标签，里面的单词还在词库里不会被删
- **单词详情弹窗可以直接编辑了**：之前只能看不能改，现在点"编辑"能直接改音标和释义（词性+中文），存错了或者自动匹配得不准都能手动修
- **数据备份**（词汇中心导入区域下方）：所有数据都存在浏览器 IndexedDB 里，之前没有任何备份手段——不小心清了浏览器数据就彻底没了。现在可以关联一个本地文件夹（跟"关联释义库文件夹"同一套技术，选一次就行），之后每 24 小时自动写一份 JSON 快照进去，也能随时点"立即备份"手动存一次，只保留最近 14 份不会无限占空间。这不是"服务器自动备份"（LanguageBridge 没有后端能替你存东西），是浏览器直接把数据写到你自己电脑的文件夹里

### 听写训练
不在顶部导航单独出现了，从词汇中心「听写」按钮进入（选完范围后仍会展示模式选择界面，不会直接跳过）。三种模式：
- **拼写测试**：按词书 + 状态 + 数量 + 顺序筛选范围，听发音写单词自动判分，错词自动标「不认识」，支持错词重听写、导出错词 TXT
- **朗读复习**：只听不写，可循环/随机播放，适合考前预热
- **听力材料**：基于文件系统访问 API（需 Chrome/Edge），选择本地音频+文本所在文件夹，浏览播放，可从文本一键提取生词并建成词书

### 阅读助手（重做：文章列表+分组、真正的划线标记）
- **文章列表**：之前所有文章挤成一堆按钮堆在顶部，现在改成正经的列表——可以搜索标题、按分组筛选、多选批量移动分组/批量AI整理/批量删除/全选
- **文章分组**：可以新建分组（比如"小红书沉浸式背单词"），导入时选好分组，或者在列表里多选后统一移到某个分组
- **选择模式默认收起**：列表默认不显示复选框，点"选择模式"按钮或长按某一行才进入，这时候左边才会出现复选框，避免平时浏览列表被一排勾选框占满
- **划线标记系统重做成一套统一的交互**（对照你 reader.js 的 `handleTap` 逻辑重写的：之前我做了"点单词弹词典卡片"和"拖选文字弹标记菜单"两套系统，选中单个词的时候两个会同时冒出来，还会导致同一段文字被重复标记两次——现在改成跟你一样，只有一套：不管是拖选一段文字还是点单个单词，都走同一个菜单）：
  - 拖选任意一段文字（单词/短语/整句都行）或者点单个单词，弹出同一个菜单：6 色调色盘（划线，跟你的 HL_COLORS 一样：sand/sage/mist/rose/lilac/clay）、复制、**问 AI**（把选中的内容直接发到悬浮面板的对话框里，AI 能读到你选的原文，不用自己打字复述一遍）；如果选中的是单个单词，菜单上还会多出"认识/模糊/不认识"三个快捷按钮
  - **点正文里已经标记过的文字，弹出的是编辑菜单**（改颜色/删除），不会再新建一条重复的标记——这是造成"标记会重复"那个 bug 的根本原因，已经修掉
  - **标记存进词书时会自动查一下释义填上**（如果关联了释义库文件夹），不再是空的等你自己手填
  - 标记坐标用的是"全局字符偏移"（把全部句子当成一篇虚拟全文来定位，而不是"在某一句里找子串"），这样即使选中的文字跨越好几句也能正确标记和高亮，不会因为跨句子就找不到、不显示
  - 左右分栏/单句对照/双语对照模式下，英文标记了，对应那句中文也会跟着高亮同样的颜色（按相交的句子高亮，不是逐字符）
- **左右分栏改成表格式对齐**：之前英文一句话换两行、中文只占一行，两栏各自往下堆会越堆越偏；现在改成"每句一行"的结构，这一行的高度撑到两边里较高的那个，保证任何时候中英文都在同一行
- 标记的内容会列在文章下方"划线标记"区域，每条可以写备注、点了跳转回原文，也可以选择**存进指定的词书**（新建或选已有的）
- 文章标题放在工具栏上方，文章列表里也能直接重命名标题（点标题旁边的铅笔图标，✓/✕ 明确确认/取消，不再只靠点别处退出编辑）
- **文章书签**：文章列表每一行、文章正文标题旁都有个书签图标，点亮代表"正在看/要看"，这类文章会自动排到列表最前面
- **文章批量分享**：列表多选几篇文章后可以"导出分享包"，打包成一个 json 文件下载；对方拿到这个文件后，在工具栏点"导入分享包"选择这个文件就能导入，标题/中英对照/笔记/划线标记都带过去
- 阅读助手页面顶栏不显示"搜索单词或释义"那个框了（跟阅读场景无关，之前占着地方没用）
- **阅读区换肤**（照搬 MyLibrary reader.js 的 `SKINS`，色值原样搬）：工具栏右侧一排小圆点，羊皮纸/米白/豆沙绿/怀旧棕/夜间/深蓝/纯黑 7 种，点哪个当场切换文章正文区的背景和文字颜色，选择会记住。默认是"羊皮纸"暖色调，不再是刺眼的白底
- **划线标记 + 学习笔记挪到左侧可折叠栏**：原来堆在文章最下面得划到底部才能看到，现在是页面左侧一个常驻的小把手，点开是个侧边抽屉，划线标记和学习笔记都在这里，随时能看、不用离开正文
- **中文那侧现在也能点了**：左右分栏/单句对照/双语对照模式下，点中文句子会弹出跟英文那边一样的标记菜单，因为是直接点中文点出来的，存的标记里中文片段是精确已知的，不用再等 AI 事后猜——这样标注和跳转对应都更准
- **标记可以发到学习笔记**：菜单里"发到笔记"那一排，点"句型"/"表达"/"原文"会把选中内容（连带你点的是中文就把对应中英文一起）追加进笔记文本框，前面带个【句型】这样的标签方便分类翻找。**如实说明一个限制**：学习笔记是个普通文本框，没法做真正的"颜色高亮"（textarea 这个东西天生不支持富文本），这里用文字标签模拟分类，不是我偷懒——真要做到彩色高亮得把笔记从文本框换成富文本编辑器，那是完全不同的另一套东西，这次没做
- **音频对轴**：工具栏"音频对轴"按钮，可以给文章关联一个真实音频文件（比如播客原声），然后放音频、逐句点"标记开始"手动对轴。做完之后跟读模式播放的就是这句话的真人原声片段，不再是 TTS 合成音——跟读列表里对过轴的句子会标"原声"。**这里如实说明技术边界**：自动把音频切成一句一句需要跑 WhisperX 那类语音识别强制对齐模型，是要后端算力的活，纯网页做不到自动化；这个是手动对轴（边听边点），准确但要花点时间，不是我偷懒不做自动的，是这个架构（纯前端+轻量静态服务器）真做不到
- **文章"已学完"标记**：列表每行和正文标题旁都多了个勾选图标，标完的文章行背景会变成淡绿色，跟其他文章区分开，方便一眼看出学过哪些
- 导入：粘贴文本 / 文件（TXT·MD·HTML·DOCX·PDF，支持多选批量导入）/ 输入网址抓取正文
- 自动清理转录稿噪声（标题行、日期行、"发言人1 00:12"这类说话人标签），并识别是否为"沉浸式背单词"类中英混杂转录稿，可一键 AI 整理成清晰文章
- 自动识别中英对照结构，三种排版切换，标题可编辑
- **学习模式**：选句子范围 → AI 梳理知识点/分析知识架构/出选择题自测，结果可跳转原文定位、可存为笔记
- **跟读模式**：逐句播放原音，点"开始跟读"用麦克风跟着念，浏览器语音识别会把你说的话转成文字，和原文比对给一个参考分。**这是文本匹配的近似分数，不是真正的语音学发音/语调评测**——评价"你有没有说对这些词、顺序对不对"，评价不了口音是否地道，这类专业发音评测需要付费的语音评测模型，本地免费方案做不到，先如实说明
- **复述模式**：除了打字复述，现在也可以点"录音复述"用嘴说，实时转文字写进复述框；写完/说完点"AI打分"，AI 会对照原文从内容完整度、语法正确性、表达地道程度给反馈和总分（需要配置好 API Key）
- 笔记：手动记录或 AI 生成，保存在本地
- AI 翻译全文：纯英文文章一键逐句补译中文

跟读和语音复述都依赖浏览器内置的语音识别（Web Speech API），只有 Chrome / Edge 支持，且需要能访问 Google 的语音识别服务（国内网络环境下可能不稳定或不可用，这点和 Free Dictionary API 一样属于外部依赖限制）。


### AI 助手
- **不再有单独的整页了**，右下角悬浮圆形按钮（可拖动，位置记住），点击打开悬浮面板；标题栏三个图标：日历（学习打卡）、齿轮（设置，就在面板里改，不会跳走）、关闭
- 设置视图：连接配置档、服务商/Base URL/API Key/模型（可拉取真实模型列表点选）、测试连接——**跟以前整页的内容完全一样，只是不用跳转了**
- 学习打卡：真实的连续打卡天数 + 今日新词/学习分钟/复习次数/正确率 + 热力图，数据来自实际使用记录
- 打卡视图里还有**学习待办**（加一条待办、打勾完成、删除）和**学习习惯**（比如"每天背10个词"，设个目标天数，每天点一下"打卡"，连续天数自动算，达标会有提示），参考 MyLibrary Quill 的日历那套数据模型，只是界面上简化成了列表（原版是月历格子，悬浮面板宽度装不下）
- 快捷操作：学习统计（真实数据，不调用AI）、随机复习一词（真实抽词+自动发音）、AI学习建议、单词讲解/造句/翻译
- AI 回复下面有"存为词库讲解"，点一下就存进对应单词的详细讲解字段（尝试从你的提问里识别是哪个单词，识别不准可以自己在提问里明确写"单词：xxx"）
- **OpenAI 兼容接口的 Base URL 请按照该服务商自己的文档填写完整路径**（通常已经带 `/v1`，比如 `https://api.deepseek.com/v1`、`https://api.gemai.cc/v1`），程序只会在后面拼接 `/chat/completions`，不会重复拼接 `/v1`
- **模型名称输入框里灰色的文字是占位提示，不是已经填好的值**——之前有个 bug：如果这一栏被清空过，界面看着像是有值（其实是占位符），但实际调用时会静默换成一个写死的默认模型（跟占位符显示的不是同一个），中转服务收到不认识的模型名就会报"No available channel"这类错误。现在已修复：模型名为空会在设置页自动补一个合理默认值，真的调用时如果发现是空的会直接明确报错提示去填，不会再悄悄换成别的模型
- **模型列表可以直接拉取，不用盲填**：填好 Base URL 和 API Key 后点"获取模型列表"，会调用服务商标准的 `GET /models` 接口拉出真实支持的模型，点条目直接填入模型名，不用自己猜/打字容易打错。**如果手打的模型名报"No available channel for model xxx"这类错误，通常是因为这个中转服务给模型起了自己的命名（可能带方括号前缀这种自定义标记），跟官方模型名不完全一样——务必先点"获取模型列表"看真实支持哪些名字，再从列表里点选，不要凭感觉手打**
- **修了个预扣费失败的 bug，这次是真找到根子了**：跟你的 `mylib_agent.py` 逐字段核对过，`_call_deepseek` 的请求体只有 `model`/`messages`/`stream`，从来不传 `max_tokens`。之前我以为把 `max_tokens` 调小能省钱，结果是反的——有些按公式预估费用的中转站，只要请求里**出现** `max_tokens` 字段就会按它重新估一次"最坏情况"预扣费，不管这个值是 2000 还是 10 都会触发；不传这个字段、让服务端用模型自己的默认值，反而不会触发这套预估逻辑，直接按实际用量算。现在 OpenAI 兼容接口这条路径完全不传 `max_tokens` 了，跟 Quill 的请求体逐字段对齐（Anthropic 官方接口这个字段是 API 强制要求必填的，这条路径保留）
- **修了个悬浮面板按钮点了没反应的 bug**：标题栏日历/设置/关闭这几个按钮之前点了没用，是因为标题栏拖动逻辑绑在了整个 header 上，按钮的点击事件被拖拽的指针捕获"劫持"了。现在只有点 header 空白处才会触发拖拽，点按钮不会再被拦截——之前反馈的"设置打不开""关不掉""不知道去哪配置 API"都是这一个 bug
- 打卡视图如果是新装还没标记过单词/没听写过，连续天数是 0、格子全灰是正常的（不是坏了），现在会显示"还没有学习记录"的提示文字
- **连接配置档**：可以把当前一套 服务商+Base URL+Key+模型 保存成一个命名配置档（类似 MyLibrary 的 Quill 面板），保存多套后用小圆点/chip 一键切换，不用来回改
- **请求会经过本机的本地服务器转发，不是浏览器直连服务商**：浏览器有跨域限制（CORS），Anthropic 官方接口特意为浏览器直连开了口子，但绝大多数第三方中转服务不会给浏览器开这个权限，直接从网页调用大概率被拦截、报一个很隐晦的错误。所以请求会先发给本机上跑的这个小 Node 服务（就是 `启动LanguageBridge.bat` 起来的那个），由它代为向服务商发起请求——这跟 MyLibrary 里 Python 后端直接发请求是同一个道理，只是"后端"换成了本机这个几十行的小服务，**全程只在你自己电脑上转发，Key 不会经过任何我们自建的远程服务器**。这也意味着 AI 功能必须通过 `启动LanguageBridge.bat`（或 `npm run dev`）打开才能用，不能直接双击 `dist/index.html` 打开静态文件
- **Key 只存本地浏览器**（配合上面的本地代理，从头到尾都不会有 Key 离开你自己的电脑）

## 三、接入释义库（英语词汇可视化学习系统）——现在不复制文件了

之前的做法是跑 node 脚本把释义库 JSON 复制进项目，几千上万个文件复制一份很占地方，你反馈之后已经换掉了。现在改用浏览器的文件夹访问能力（跟"听力材料"是同一套技术），**直接读取你本地文件夹，不做任何复制**：

1. 进词汇中心，导入词书区域下方"关联释义库文件夹"，选一次你本地的 `word_explanations` 文件夹
2. 会扫描一遍建索引（文件名是哈希值看不出对应哪个单词，所以必须打开每个文件读一下 `word` 字段，这一步只存一个几十 KB 的"单词→文件名"映射表，不会复制原始文件），词条比较多的话扫描要几十秒到几分钟，有进度提示
3. 扫描完之后：
   - 导入单词表时自动按这个索引匹配补全音标/释义/例句等，直接读原文件夹，不经过任何复制
   - 词汇中心可以点"导入完整释义库"，把全部词条变成可浏览词书，按 高中/CET6/考研/托福/雅思 等分类自动拆书
   - **现在支持子目录递归**（有些释义库会按字母/分类分文件夹存放），扫描完如果一个词条都没识别出来，会告诉你具体发现了多少文件、多少个 .json、失败原因是什么（比如没有 word 字段），不再是"什么都没发生"式的静默失败
   - **修了个已存在的词被整库导入晾在一边的 bug**：之前如果一个词你自己先导入过（比如听力单词表），后面点"导入完整释义库"时这个词会被直接跳过——不光没有补全释义，连"这个词其实也属于 CET4/SAT 等分类词书"这件事都没记录，跟它没关系似的。现在改成：已存在的词会补全缺失字段（**不会覆盖你原来正确的释义**，只补音标/词性这些空着的部分），并且会正常加入它在释义库里对应的所有分类词书——**一个词现在可以同时属于你自己的词书和多个分类词书**，不再是"先到先得，占了位置后面的就进不来"
4. 关联只需要做一次，下次打开浏览器会记住这个文件夹（Chrome/Edge 的标准授权机制），除非你换了浏览器或者清了浏览器数据才需要重新关联
5. 想换文件夹或者不想再用了，点"取消关联"

这个功能需要 Chrome / Edge（跟听力材料同样的限制）。**如果你之前已经跑过旧版的复制脚本**，`public/data/word_explanations` 目录下那 15000+ 个复制出来的文件现在已经用不上了，可以手动删掉释放磁盘空间；`scripts/build-explanations-index.mjs` 这个脚本还留着做兼容（万一有人的浏览器不支持文件夹关联），正常情况下不需要再跑它了。

## 四、发音说明

- 单词：有道词典真人语音（`dict.youdao.com/dictvoice`，默认美音），失败自动回退浏览器 TTS
- 例句/短语/自由文本：浏览器 TTS
- 改发音口音：`shared/core/audio.ts` 里 `playWord(word, 'uk')`

## 五、数据存储

全部数据存在浏览器 IndexedDB（`LanguageBridgeDB`），包括单词、词书（分组）、阅读文章笔记。AI 相关设置（Key/模型等）存在 `localStorage`。清空浏览器数据会清空这些内容，请注意浏览器设置里"清除缓存时是否保留网站数据"。

## 七、已知限制 / 后续可选项

- 拼写听写目前只支持"听英文写英文"方向；"看词写中文释义"因同义词判分模糊没做，如需要可以做成选择题形式的辨认模式
- 网址抓取正文对有反爬机制的网站会失败，可改用复制粘贴或文件导入
- 打印功能（V14 里有）没有搬过来，现在数据在 IndexedDB 里，导出 TXT 更实用；如果需要打印版单词表可以再加
- PDF 提取文本是按坐标顺序拼行，遇到分栏排版（听力同义替换册子、词汇表这类左右两栏的版式）容易把两栏内容交叉拼在一起，效果不如 TXT/DOCX 可靠，复杂 PDF 建议先手动转成 TXT 或直接复制粘贴
- DOCX 表格里的文字 mammoth 提取出来会按行拼接，如果是严格的表格型词表（比如"单词|音标|释义"三栏表格），提取顺序可能跟表格视觉顺序对不上，需要的话可以针对表格结构单独适配
- AI 整理转录稿单次最多处理约 6000 字符，超长文章会被截断，遇到很长的材料可以先手动分段
- **跟读打分是文本匹配的近似分数**（识别出的文字和原文比对），不是专业的语音学发音/语调评测；真正的发音评分（准确度到音素级别、语调曲线对比）需要接入专门的付费语音评测服务，目前的免费方案做不到，如果对这块有专门预算可以后续接一个真正的发音评测 API
- 语音识别（跟读、语音复述）依赖浏览器内置的 Web Speech API，只支持 Chrome/Edge，且底层是调用 Google 的识别服务，国内网络环境可能不稳定
- 整库导入的词条如果特别多（上万级别），首次导入耗时会比较长（几十秒到几分钟），且 IndexedDB 会占用相应的浏览器本地存储空间，属于一次性成本
- 词族/近反义词点击跳转，只有当那个词已经在你的词库里（无论是自己导入的还是从释义库整库导入的）才能跳转成功，没收录的词会提示去 AI 助手查
