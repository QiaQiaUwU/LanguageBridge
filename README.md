# LanguageBridge

> 本地运行的英语学习工作台。词库、打字练习、3D 词汇关系图、阅读助手、听写检测在一个应用里，数据全部存在自己电脑上。

## 这是什么

市面上的背单词软件大多把"记住拼写"当终点。这个项目想解决的是另一件事：**一个词在你的词汇网络里处在什么位置**。

三条主线：

1. **词汇网络可视化** — 一万多个词按话题聚成星团，同根词、近义词、反义词是星团之间的连线。可以从「情感」钻到「积极情感」再钻到具体词族。
2. **对照真实材料学** — 导入整本书或资料，自动分章、中英逐句对照、划词入库、跟读对轴。
3. **练到能写出来** — 打字判定逻辑对照 [TypeWords](https://github.com/zyronon/typing-word) 实现，复习排期用 FSRS。

全程离线可用，只有 AI 补全那一步需要联网。

## 跑起来

需要 Node.js 18 以上。

**Windows 最省事**：双击 `LanguageBridge.vbs`。首次运行会在桌面建一个图标，之后从桌面点就行，不弹命令行窗口。

几个启动器的区别：

| 双击哪个 | 得到什么 |
|---|---|
| `LanguageBridge.vbs` / `启动LanguageBridge.bat` | 浏览器里打开，日常用这个 |
| `以桌面软件方式启动（含悬浮球）.bat` | Electron 桌面窗口，带**桌面悬浮球** |
| `打包桌面版EXE（含悬浮球）.bat` | 打成独立 exe，可以发给别人 |
| `停止LanguageBridge.bat` | 关掉后台服务 |

**桌面悬浮球**：点一下开对话框，长按调出播放操作台（只在有音频在放时才给）。
播客在后台放着的时候，球上会显示文章名和当前这句，跟着播放滚动。

**命令行**：

```bash
npm install
npm start          # 等同 node scripts/server.mjs
```

首次启动会自动装依赖并构建，之后只在源码真的变过时才重新构建。浏览器会自己打开 `http://127.0.0.1:58712`。

已经在跑的时候再点一次启动器，不会开出第二个服务，而是把浏览器指到已有的那个。端口被占会自动往上找一个空的，并把新端口写回 `port.txt`。

### 可选：后端

`backend/` 是一个 FastAPI 服务，把词条、文章、学习记录落到磁盘文件，作为浏览器 IndexedDB 之外的第二份存储。不启动也能用，但浏览器数据被清掉就没有兜底了。

```bash
cd backend
pip install -r requirements.txt
python main.py
```

### 打包成 exe 发给别人

**推荐**：双击 `打包桌面版EXE（含悬浮球）.bat`（Electron 路线）。
它会按顺序跑「装依赖 → 构建前端 → 打包」，产物在 `dist-desktop\`，带桌面悬浮球。

`一键打包EXE.bat` 是早期的 pkg 路线，产物在 `dist-exe\`。它需要联网下载 Node 二进制，
经常下不到而失败；打出来的也没有悬浮球。

词库放在 exe 旁边而不是塞进去，因为打包进去的是只读快照，而 AI 补全、收生词、改标签都要往词库里写。

## 功能

| 模块 | 做什么 | 要联网调 AI 吗 |
| --- | --- | --- |
| **词汇中心** | 考试 / 话题 / 词根词缀三个维度并行叠加，再叠一层认识 / 模糊 / 不认识 | 否 |
| **词汇宇宙** | 3D 力导向关系图，四类关系连线，大类 → 话题 → 词族逐级钻取 | 否 |
| **学习 / 打字** | 逐字符实时判定、跟写 / 拼写 / 自测多种练习类型，FSRS 排期 | 否 |
| **阅读助手** | 导入整本书自动分章，逐句对照、划词入库 | 整理和补译要 |
| **影子跟读** | 逐句听、跟读、录音、原声与自己连着放对比 | 否（难词讲解要） |
| **听写检测** | 单词模式逐个来，列表模式一屏铺开统一判分，错词循环闭环 | 否 |
| **卡片消消乐** | 单词和释义打乱混排，点对了消掉，点错了进错词本 | 否 |
| **卡片背单词** | 翻卡片评价认识程度；开着打字练习就要照着敲一遍才翻面 | 否 |
| **学习记录** | 笔记、章节笔记、AI 生成的文章汇在一处，可改可删 | 否 |
| **场景学习** | 按话题或词表生成成套教材、造句训练、播客稿 | 要 |
| **AI 助手** | 问答，以及直接操作软件（建词表、加词、定提醒） | 要 |

### 词汇宇宙

按「核心词做恒星」组织：每个词族只画核心词，衍生词跟着核心词归入所在星团。这样分类不会被衍生词污染（`aggressiveness` 不会因为词族关系被拖进「积极情感」），节点数也从五千多降到几百，力学模拟顺畅。

三层钻取：大类星团（情感 / 科技 / 自然与环境…）→ 话题星云（积极情感 / 消极情感）→ 词族。每一层悬停时整团亮起，点击飞进下一层，面包屑可以点回任意一级。

按掌握程度上色时亮度来自记忆曲线：学熟了亮，长期不复习自己暗下去。

### 导入材料的几种方式

| 方式 | 说明 |
| --- | --- |
| 贴文本 | 直接粘进去，中英对照 / 纯英文 / 纯中文都认 |
| 上传文件 | txt、docx、pdf |
| 上传音频视频 | 视频会抽音轨，原视频不保存 |
| 贴链接 | B 站、YouTube |
| 批量导入音频 | 在书的目录里，一次选一堆，自动跟章节配对 |
| 导入词表 | 一行一个词，`词;释义` 或 `词 释义`，格式示例见 `docs/示例单词表.txt` |

批量配对的规则：先归一化（去扩展名、去序号前缀、去标点），**优先按数字序号配**，
其次算名称相似度，最后贪心取互不冲突的组合。
`01_rainy.mp3`、`02 moon.mp3`、`ch03-winter.m4a` 这种混着写也能对上。
配好的结果会列出来让你确认、可以逐条移除，确认后才排队跑对轴。

导入时会先判断这是什么稿子再决定怎么处理：中英混杂的口播稿、纯英文、纯中文、
已经是对照稿、篇幅长且有章节结构，五种走五条不同的路。判断理由会显示出来，
出问题时能看出是判断错了还是处理错了。

### 长文与整本书

导入一本书时，分章和翻译是分开的两步：

1. **结构** — 优先用文件自身的标题层级（`##`、编号题目）。识别不出来时才让 AI 判断「哪几行是章节标题」，只回行号，逐条用原文校验，编造的行号直接丢弃。
2. **正文** — 中英配对、断句全部由本地代码做，确定性的，不经过模型。
3. **补译** — 只把缺译文的句子送去翻译，每批 20 条、可断点续跑。章节号这类结构行原样保留，不浪费一次请求。

三种输入都能处理：中英对照（段内配对，中英顺序不限）、纯英文、纯中文（按中文标点断句，英文栏留空等翻译）。

### 影子跟读

给文章配音频后逐句跟读。三条路拿到「每句从第几秒到第几秒」：

1. **导入字幕**（`.srt` / `.vtt`）— 最准最快
2. **拖入视频** — 本机 `ffmpeg` 抽音轨，原视频不保存
3. **自动转写** — 本机跑 whisper，音频不出这台电脑

还有第四条，也是现在最常用的：**本机 wav2vec2 强制对齐** —— 在 Web Worker 里跑，
音频不出这台电脑，可以同时跑几篇（并发上限在设置里调，默认 1）。

对轴之后可以连续播放：读到哪句高亮哪句、自动滚动。控制条上一个下拉选循环方式
（不循环 / 单句 / 本篇 / 整本），一条拉条切换调音量、速度还是句间停顿。

**真正的跟读练习**：打开「跟读」开关后，点播放 = 一句原声 + 一段留白，
留白长度由「句间停顿」拉条决定。留白期间自动开录音，说完自动停（静音 1.6 秒）。

- 录音时一排竖条跟着说话跳动，每根对应一个频段
- 录完显示时长，可以删掉重录
- 控制条上多一个「放什么」：原声 / 我的录音 / 原声 → 我的。
  想把自己录的连着听一遍，就是「我的录音」+「本篇循环」，速度和停顿照样能调
- 控制条上点「对比」，逐句列出原声多长、自己读了多久、语速偏快还是偏慢
- 把英文关掉就是复述练习，不是另一个模式
- 练之前点「难词」先过一遍拦路的词

**这里不打分。** 试过本机识别 + 比对算分那条路，识别质量撑不住短录音，
算出来的分只会误导人。留下的是能客观量出来的时长对比，以及原声和自己连着听。

跟读模式下同样能划线做笔记、悬停查词。

**一本书连着听**：控制条上的循环方式选「整本循环」，一章放完自动打开下一章接着放，
最后一章完了回到第一章。切到哪一章界面就跳到哪一章，
目录栏里正在播的那一章会挂一个闪动的小喇叭，随时知道现在放到哪儿。

### 学习 / 打字

一轮完整流程：新词跟写 → 拼写 → 听写 → 默写，旧词自测 → 听写 → 默写。
练习模式可以在设置里换（只自测 / 只听写 / 只默写 / 随机复习）。

- 跟写和拼写按组交替：跟写完一组（默认 7 个）就回头拼写这一组，再跟写下一组，组的大小在设置里可调
- 单词卡下面一排：标记已掌握、写笔记、收藏进词表、跳过，都有快捷键
- 例句和短语里的词能点开查释义，正在练的那个词高亮
- **练到一半退出会存断点**，下次进来问「接着练」还是「重新开始」；
  选重新开始也不会丢成绩，上一轮练出来的先记进复习计划
- 练完的结算页有本周记录和词表进度

### 笔记与学习记录

划到的内容自动整理进右侧笔记栏，点笔记里的词能跳回原文对应的句子。
书的每一章有自己的笔记页，顶部可以翻页或直接下拉切换。

侧栏的「学习记录」把三类东西汇到一处：自己记的笔记、章节笔记、场景学习用 AI 生成的文章。
每条都能改标题、改内容、删掉 —— AI 生成的那些是花过额度的，不该生成完就找不着。

整理文章之后标记会按原文重新定位 —— 句子重排了旧下标就不能用了，
按标记的文字到新句子里找回去，找不到才放弃。

### 桌面悬浮球

用 `以桌面软件方式启动（含悬浮球）.bat` 打开时才有。

- 点一下：开对话框
- 长按：调出播放操作台。**只在有音频在放时才给** —— 闲着的时候长按只会抖一下，
  因为那时候面板是空的
- 播客在后台放着时，球上显示文章名、当前这句和下一句，跟着播放滚动
- 有音频在放时球上多一圈提示环，一眼能看出长按有东西

## 数据放在哪

刚 clone 下来是空的 —— `data/` 和 `resources/` 都不进仓库，它们是使用者自己的资料。

| 目录 | 装什么 | 能不能删 |
| --- | --- | --- |
| `resources/word_explanations/` | 词库原本，一个词一个 JSON | **不能**，这是原始资料 |
| `resources/articles/` | 阅读助手的文章 | 不能 |
| `resources/media/` | 文章关联的音频（选的、或从视频抽的） | 不能，删了就要重新导入 |
| `resources/word_index.json` | 分类索引，从词库扫出来的 | 能，设置页一键重建 |
| `data/words.json` | 词库 + 学习状态的合并快照 | 能，设置页一键重建 |
| `data/` 下其余 | 学习状态：词表、记忆卡片、活动日志、设置 | 不能，删了进度就没了 |

一句话：**`resources/` 是原本，`data/words.json` 是可再生的缓存，`data/` 下其余是学习记录。**

### 为什么还要 `data/words.json`

它不只是"少读几个文件"那么简单。词库那一万五千个 JSON 里**没有学习状态** ——
认识/模糊/不认识的标注、词条 id（词表引用的就是 id）、加入时间、AI 补全的记账，
这些是用起来才产生的，词库里没有也不该有。

所以它是**词库 + 学习状态的合并快照**：删掉之后点「重建词库索引」能从词库重新生成，
重建时会先把旧快照里属于用户的那部分抠出来、重建完逐条贴回去 —— 学习进度不会丢。

规矩是"所有信息以词库为准"：AI 补全、手工编辑都要同时写回
`resources/word_explanations/`，只写快照的话下次重建就没了。

配套教材、色卡、界面偏好这些存在浏览器 `localStorage` 里，不占目录，
也不会跟着 `data/` 一起备份 —— 换台机器要重新生成。

## 自定义配色

划线荧光笔和词汇宇宙**共用一套色卡**。设置页「自定义配色」：

- 色卡可以逐个改（每格一个取色器）、删、加，也能从图片取色（并进色卡，不覆盖已有的）
- 多套色卡可以另存、切换、删除，内置三套（默认 / 灰调 / 暖木）
- 点色块「上膛」，再点划线色或词汇宇宙里任意一个分类，颜色就染过去

取色算法搬自作者另一个项目 MyLibrary 的书架取色（72×72 采样 → 远距播种 16 簇 →
10 轮 Lloyd 迭代 → 去掉太接近的），纯 canvas 实现，没引取色库。

### 备份

设置页「整体备份」导出一个文件，含词条、词表、记忆卡片、错词本、已掌握、学习设置、配色覆盖。换电脑之后「恢复备份」读回来。

浏览器里那份只是缓存。启动了后端的话，阅读助手里「从后端恢复」可以在浏览器数据被清掉之后把文章拉回来。

## 配套教材

练习设置里把「每学 N 个新词插一次场景学习」设成非 0，这个词表就会有一套自己的教材。

生成时做三件事：**按话题把词分课**（一课 12–28 个词，词条自带话题够用就不花钱，
覆盖率不足才问模型）、**按课排出学习顺序**、**逐段写课文**（同话题的段归一篇，
一篇最多 5 段；零散话题攒几个凑一篇）。

学的时候：顺序按教材走，某一课的词全学完了就把那一段课文端出来读，
文中的词鼠标停一下出释义。一篇的段都读完了会拼成完整的一篇，可以存进阅读助手，
从此就是普通文章 —— 能对轴、能跟读、能划线。

**教材没生成完就不给开始学**（学词顺序要靠它）。主页那个按钮会变成「生成配套教材」，
点了在右下角任务里跑，能看进度、能停、停了下次接着写。每段写完立刻落盘。
主页「配套教材 N/M 段」能查看每一课的话题、词数、写没写。

- **造句训练** — 用目标词写一句，检查后出问题的片段在原句里标红（悬停看类型和原因），
  错误类型跨会话累积，能看出自己老犯哪一类

## AI 助手能动手

除了问答，可以直接让它操作软件：

> "建个词表叫雅思核心，把我刚查的词都加进去"

会改数据的操作**一律先弹确认条**，点了才执行；执行结果会回填给模型，
所以它不会编造"已经建好了"。支持：建词表、改名、加词、查词、定时提醒、跳页面、定位文章。

## 哪些功能会调用 AI

会联网、消耗额度的：

| 功能 | 在哪 |
|---|---|
| AI 整理文章 / 补译文 / 补英文 / 识别章节 | 阅读助手 |
| AI 生成学习笔记 | 阅读助手 |
| 跟读「难词」 | 影子跟读 |
| 场景材料、造句检查、播客稿 | 场景学习 |
| 单词释义补全 | 词库设置 |
| AI 助手对话与操作 | 悬浮球 |

**不调用 AI 的**：音频对轴（本机 wav2vec2）、录音与声波、录音时长对比、
词汇宇宙、听写、测试、卡片消消乐、笔记存储、词典数据补全（那是查词典不是生成）。

### 配置

悬浮球 → 设置里填 API Key、Base URL（多数中转站要以 `/v1` 结尾）、模型。

**「长任务专用模型」**：有些中转站按模型的上下文窗口预扣费，选了百万上下文的模型，
一次请求就要预扣几百块余额，报 403「预扣费额度失败」——这跟请求大小无关。
整理转录稿这类长任务在这里填个小窗口的便宜模型即可，主模型不用动。
设置里的「测一下额度够不够」会连发三个大小不同的请求，一次判断是请求太大还是账户门槛问题。

## 后台任务

对轴、整理这些要跑几分钟的活儿都登记在右下角的任务面板：能看到进度、能单独停止、
三分钟没新进度会提示可能卡住了。跑完或失败会留一条等你点掉，失败会写明具体原因。

## 词典数据

例句、短语、近义词、词根、词源这些是**词典数据，不由模型生成**。设置页
「从 TypeWords 词典补例句 / 短语 / 近义词」直接拉 TypeWords 用的那份词典
（`files.typewords.cc`），按词形匹配后只补空缺，已有内容不覆盖。

解析逻辑 `shared/core/typewordsDict.ts` 是对其 `convertToWord` 的逐行移植，
所以同一条原始记录在两边解析出的结构完全一致。

## AI 补全

一个词条有七项：**中文释义 / 音标 / 例句 / 考纲来源 / 话题 / 词根词缀 / 词族**。
免费词典能补前三项里查得到的那部分，剩下的交给模型。设置页「AI 补全」，
用右下角 AI 面板里配好的连接（key 存在浏览器 localStorage，不进仓库也不上传）。

**缺什么补什么**：先扫一遍看每个词缺哪几项，按「缺的是同一组」归堆再切批，
提示词只问这批真缺的项，已有的值一律不动。跑过的按项记账 ——
早期只问过话题的词，之后缺释义照样会被排进去。每批立刻落盘，中断了下次接着走。

**想重跑某一项**：补全区里点开，勾中文释义 / 考纲来源之类，
只跑选中的项、范围内的词全部重跑、**允许覆盖已有值**。跟上面那个「开始补全」
是两个独立的动作，互不影响。

`word` 字段不像英文词的（存的是释义或词性缩写）一律不送 —— 一条脏数据会让模型
纠结"这是不是笔误"，把推理当正文吐出来，整批十二个词一起废掉。

### 推理模型

带思考过程的模型（deepseek-r1、gemini thinking 之类）要 JSON 时会出问题，
处理分四层：请求里直接发关闭思考的参数（各家名字不同，一次都带上，
服务端不认就脱掉重发）→ 回复里剥 `<think>` 一类标签 →
`reasoning_content` 里按括号配对捞 JSON → 输出被截断就加大配额重试。

即便如此，**非推理模型（如 `deepseek-chat`）跑这个任务仍然稳得多**。

## 技术栈

Vue 3 + TypeScript + Vite + Pinia，3D 图用 [3d-force-graph](https://github.com/vasturiano/3d-force-graph) / three.js，本地存储 IndexedDB（idb），可选后端 FastAPI。

```
apps/
  word-core/           词汇中心与关系图组件
  study/               学习、打字、主页
  dictation-app/       听写检测
  reading-assistant/   阅读助手
shared/
  core/                切分、判定、调度、数据库等无 UI 逻辑
  stores/              Pinia
backend/               可选的 FastAPI 落盘服务
scripts/               启动器、构建、模板自检
```

## 开发

```bash
npm run dev          # 开发服务器
npm run check        # 模板结构自检：标签配对、v-if 链完整性
npm run build        # 自检通过才构建
npm run type-check   # vue-tsc
npm run test:unit    # vitest
```

`npm run build` 前置了模板检查，是因为批量编辑很容易把 `v-else` 链打断或者删掉正在被调用的函数，而这类错只在构建时才暴露。

## 这个项目的来历

前身是我自己的 **VocabVerse** —— 一个只做词汇关系可视化的小工具，就是现在「词汇宇宙」这一块。用了一段时间发现光看关系图不够：能看出词之间的联系，但没有地方去练，也没有真实材料去用。

于是往两边扩：往下接了打字与听写，往上接了整本书导入与逐句对照。词库、配色、关系模型这些底子都是从 VocabVerse 带过来的。
