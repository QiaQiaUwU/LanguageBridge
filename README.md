# LanguageBridge

> 本地运行的英语学习工作台：词库与 3D 词汇关系图、阅读与试题、影子跟读、听写、打字练习放在一个应用里，数据全部存在自己电脑上。

市面上的背单词软件大多把「记住拼写」当终点。这个项目想解决的是另一件事：**一个词在你的词汇网络里处在什么位置，以及你在真实材料里怎么遇到它**。三条主线：

1. **词汇网络** —— 一万多个词按话题和词根组织成两棵树、画成星系，近义、反义、同根、派生是连线，每个词都能生成关系笔记。
2. **真实材料** —— 文章、整本书、雅思阅读 / 听力 / 作文试题导进来，逐句对照、划词入库、跟读对轴、按试卷的样子做题。
3. **练到能写出来** —— 打字判定逻辑对照 [TypeWords](https://github.com/zyronon/typing-word) 实现，复习排期用 FSRS，另有逐句听写、卡片、造句。

全程离线可用，只有标了「AI」的功能需要联网。

## 快速开始

需要 Node.js 18 以上（诊断脚本需要 22.6 以上）。

| 双击哪个 | 得到什么 |
|---|---|
| `LanguageBridge.vbs` / `启动LanguageBridge.bat` | 浏览器里打开，日常用这个。首次运行会在桌面建图标，不弹命令行 |
| `以桌面软件方式启动（含悬浮球）.bat` | Electron 桌面窗口，带桌面悬浮球 |
| `打包桌面版EXE（含悬浮球）.bat` | 打成独立 exe，产物在 `dist-desktop\`，可以发给别人 |
| `停止LanguageBridge.bat` | 关掉后台服务 |

命令行：

```bash
npm install
npm start          # node scripts/server.mjs，浏览器自动打开 http://127.0.0.1:58712
```

首次启动会自动装依赖并构建，之后只在源码变过时才重新构建。已经在跑时再启动一次，不会开第二个服务，而是把浏览器指到已有的那个；端口被占会自动往上找，并写回 `port.txt`。

`一键打包EXE.bat` 是早期的 pkg 路线，要联网下载 Node 二进制、经常失败，也没有悬浮球，不推荐。词库放在 exe 旁边而不是打进去，因为 AI 补全、收生词、改标签都要往词库里写。

**可选后端**：`backend/` 是 FastAPI 服务，把词条、文章、学习记录落到磁盘，作为浏览器 IndexedDB 之外的第二份存储。

```bash
cd backend && pip install -r requirements.txt && python main.py
```

## 词汇

### 词汇中心

搜索框在最上面，下面一行是所有词表，放不下时左右滚动（滚轮或按住拖动）。从主页「我的词表」点进来会直接选中那个词表，不用再从「全部单词」里找。

各页显示的词数只算词库里真实存在的词，已删除、已合并的旧引用不计入。「全部单词」是所有词表的并集，「释义库」只是释义库导入的那一批，所以两者数字不同。

### 词汇宇宙

按「核心词做恒星」组织：每个词族只画核心词，衍生词跟着核心词归入所在星团，分类不会被衍生词污染，节点数也从几千降到几百。

- **话题树**：大类 → 话题 → 小类 → 细类 → 词族。前两层来自词条的话题字段；往下是本地算法分的，跑过「话题树梳理」的话题按 AI 归类建（见下文）
- **词根树**：词根列表按归一后的词根算，梳理合并过的 spec / spect / spic 是同一项；每项带笔记入口
- **逐层钻取**：点树里任意一层，星图换成这一层的词，下一层各组成为星云；面包屑回到任意一级
- **关系网**：以一个词为中心，连线是近义、反义、派生、同根，「扩散层数」决定铺几层；单击选中，**双击换中心**。节点按话题聚大团、按词根聚小团，排布和两棵树对得上
- **易混词**只收真会看错的：差一个字母的直接算，差两个字母的要求开头至少三个字母相同（`remark` / `remain` 算，`market` / `basket` 不算）
- 按掌握程度上色时亮度来自记忆曲线：学熟了亮，长期不复习自己暗下去

### 词汇笔记

右侧栏「详情 / 笔记」两个页签。

**关系笔记**是单词笔记的默认视图，和星系图用同一份关系数据 —— 图上画出来的词，笔记里一定有。以这个词为中心分四块：派生、同根、近义、反义，空块不显示，四块各用一支荧光笔。扩散层数选 2 时，每个相关词下面再缩进列出它自己的派生和近义、反义词，用第二支荧光笔。笔记里点任意一个词，就切到以它为中心的星系和笔记。

**从单词进词根**：单词详情「拆词」一栏里的前缀、词根、后缀可以点，点了跳到以这个词素为中心的词根笔记，中间的星系同时换成含这个词素的词。

另外四种笔记对应常见的手写单词笔记：

| 类型 | 像这样的笔记 | 组织方式 |
| --- | --- | --- |
| 词根族 | port = carry → export / import / transport | 按前缀分支，派生词挂在核心词下，拼写像但词根不同的列为易混 |
| 同义族 | 贫穷的 poor → impoverished / destitute / indigent | 同词性，附派生、短语、同词根延伸 |
| 话题族 | 信息传播 → disseminate / circulate / rumor | 话题下按小组分支，从话题树任意一层都能生成；点词跳到它的关系笔记 |
| 拆解图 | atmosphere → atmo + sphere → hydrosphere → … | 多层思维导图；生成不出内容的词不显示这一项 |

每个词都带证据与置信度，只凭拼写猜的默认隐藏。两种版式（手帐清单、思维导图），可保存到学习记录、导出图片或 Markdown。「校对」让 AI 删掉不属于这组的词、补漏掉的常用词，AI 不改已有释义。算法说明见 [`docs/词汇笔记算法.md`](docs/词汇笔记算法.md)。

### 两棵树的梳理

设置页「AI 补全」前两行。本地算法能把树搭起来，但分得准不准、哪些写法其实是同一个词根，它判断不了，这两件事交给模型。

- **话题树梳理**：前两层（大类、话题）来自词条的话题字段，不动，也不把词挪到别的话题。对每个话题，先把最多 160 个样本词（带释义）交给模型设计 4~10 个小类、每类 0~6 个细类，再把这个话题的全部词一批 80 个逐词归类，哪类都不像的放「其他」。一个细类超过 30 词时下面再用本地算法切一层；没归到的词放「未梳理」。一万七千词大约 220 次请求
- **词根梳理**：全部词根（写法、释义、例词）按首字母和释义排好，一批 250 个交给模型，合并同源异形的写法，选一个代表写法、给统一释义。代表写法必须是组里真有的；已按意思拆开的同形异义词根（port「搬运」/ port「港口」）不参与。结果只是一张「写法 → 代表写法」对照表，词条本身不改

两种都是每批跑完立刻存。开头连续两批失败会停下并显示原因；有批次失败或中途停下时，按钮变成「补跑剩下的 N」，只送没处理完的。「还原（N）」清掉梳理结果，回到本地算法。

### 词库维护与补全

一个词条有七项：**中文释义 / 音标 / 例句 / 考纲来源 / 话题 / 词根词缀 / 词族**。

- **词典数据不由模型生成**：设置页「导入词表」里加载 TypeWords 用的那份词典（`files.typewords.cc`），「补例句」按词形匹配、只补空缺。解析逻辑 `shared/core/typewordsDict.ts` 逐行移植自其 `convertToWord`。TypeWords 的 `relWords` 标着「词根」，其实是词族领头词（abandonment 的「词根」是 abandon），所以归进词族；早期版本写进过词根词缀的，统一当作没拆过
- **AI 补全**（设置页）：先扫每个词缺哪几项，按「缺的是同一组」归堆切批，只问真缺的项，已有值不动；跑过的按项记账，每批落盘、可断点续跑。「重跑指定项」只跑勾选的项并允许覆盖。`word` 字段不像英文词的一律不送，免得一条脏数据拖垮整批
- **合并重复词条**：同名词条合并，缺的字段互补，词表引用改指向留下的那条
- **修复工具**：工作缓存、词表引用、词库索引、数据库体检、批量改标签
- **诊断**：`npm run family:check -- --coverage` 报告各字段覆盖率，以及**词根树体检**（只有前后缀的、词根就是词本身的、没释义的、孤立的、写法相近却没合并的，各举例）。脚本在 Node 里跑，看不到浏览器里的梳理结果

可选外部数据：把 [ECDICT](https://github.com/skywind3000/ECDICT)（MIT）的 `resemble.txt`、`wordroot.txt` 放进资源目录的 `ecdict/`（与 `word_explanations` 同级），重启后同义族和词根族会用上。

## 阅读助手

### 导入

| 方式 | 说明 |
| --- | --- |
| 贴文本 | 中英对照 / 纯英文 / 纯中文 / 试题都认 |
| 上传文件 | txt、docx、pdf |
| 上传音频视频 | 视频会抽音轨，原视频不保存 |
| 贴链接 | B 站、YouTube |
| 批量导入音频 | 在书的目录里一次选一堆，自动跟章节配对：先按完整编号（`8-1`、`5-2`），再按名称相似度，列出来确认后才排队对轴 |
| 导入词表 | 一行一个词，`词;释义` 或 `词 释义`，示例见 `docs/示例单词表.txt` |

导入时先判断是什么稿子再决定怎么处理：试题、中英混杂的口播稿、纯英文、纯中文、已是对照稿、有章节结构的长文，各走各的路，判断理由会显示出来。

### 试题

从做题网站整页复制的雅思试题直接贴进来（或上传 txt / docx / pdf），会认成试题，按试卷的样子排：正文和题目左右对照，两边各自滚动，页面用满宽度。试题默认单句对照（在试题里切版式不改全局偏好）。

| 类型 | 左边 | 右边 |
| --- | --- | --- |
| 阅读 | 文章正文 | 各题组 |
| 听力 | 「听力原文 / Transcript」后面的原稿 | 各 Part 的题组；Part 标题显示在题组上方 |
| 作文 | 题干、配图、自己写作文的框（实时字数） | 范文（「范文 / Sample answer」之后），照常翻译划线 |

题型渲染：

- **判断题**（TRUE / FALSE / NOT GIVEN、YES / NO / NOT GIVEN）：选项含义排成两列，每题一排单选
- **单选题**：每题列出 A~D 选项；**多选题**（Choose TWO letters）：一张选项表打勾，勾满自动顶掉最早那个
- **配对题**（段落标题 i~x、人物 A~E、信息出处）：选项表列在上面，每题一个下拉框
- **笔记 / 表格 / 表单 / 摘要填空**：按原来的样子排，空位就地填；被网页甩到下一行的后半句接回原位；摘要后面带选词框的，空位改成下拉选字母
- **句子填空**：题干里的「……」「____」就地变输入框

正文照常分句、翻译、划线、查词。题目里的词也能点开查词、收藏；正文里没有、只在题目里出现的词收藏后同样进这篇的生词表；划过线、收过的词在题目里也会染上颜色。**题目会自动翻译一次**（显示跟随中英开关），缺的点「翻译题目」补。作答随文章保存，底部显示做了几题。

配图（作文图表、听力地图）：上传 docx 时文档里的图片自动带进来；上传 pdf 时，画了图片的那几页整页渲染成图带进来（最多 3 页，纯矢量画的图表认不出，截图粘贴即可）。也可以在题目栏点 ＋ 选图，或直接 Ctrl+V 粘贴；点图放大。

网页上的计时、账号、「收藏本题」「题目纠错」这些按钮文字自动去掉；`a . . . thorough` 这种省略号不再被切成单独一句。以前当普通文章导进来的试题，打开时自动转过来：已有译文按原句对回去，划线重新定位，章节目录去掉。

### 版式与分段

三种版式：单句对照、左右分栏、**双语对照**。双语对照**按自然段排**：一段英文紧跟这段的中文，不再整篇堆成两大块。段落按原文的空行找回来；原文本来没分段的（转录稿一整坨），按长度和转折词（However、Another、Finally…）切，4~6 句一段。

分句会把句末的右引号、右括号归到前一句（不再单独占一行），`Mr.`、`Dr.`、`U.S.`、`J. K.` 这类缩写后面不断句。

### 长文与整本书

导入一本书时，分章和翻译是分开的两步：

1. **结构** —— 优先用文件自身的标题层级（`##`、编号题目）。识别不出来才让 AI 判断「哪几行是章节标题」，只回行号，逐条用原文校验，编造的行号直接丢弃
2. **正文** —— 中英配对、断句全部由本地代码做，不经过模型
3. **补译** —— 只把缺译文的句子送去翻译，每批 20 条、可断点续跑

一本书连着听：循环方式选「整本循环」，一章放完自动打开下一章。

### 影子跟读与对轴

给文章配音频后逐句跟读。拿到「每句从第几秒到第几秒」有四条路：导入字幕（`.srt` / `.vtt`）、拖入视频抽内嵌字幕、本机 whisper 转写，以及最常用的**本机 wav2vec2 强制对齐**（Web Worker 里跑，音频不出这台电脑，并发上限在设置里调）。

**不朗读的内容不对轴**：试题的题目本来就不在正文里；听力原文里夹的「Part 1」「Questions 1–5」「Example」这类行标成跳过，对轴只用要朗读的句子，结果再放回原位，不会把后面整段带偏。

跟读模式：打开「跟读」开关后，点播放 = 一句原声 + 一段留白，留白期间自动录音、静音 1.6 秒自动停。录完可以删掉重录；「放什么」可选原声 / 我的录音 / 原声 → 我的；「对比」逐句列出原声和自己的时长。**这里不打分** —— 本机识别撑不住短录音，算出来的分只会误导人。把英文关掉就是复述练习。

### 逐句听写

阅读助手文章页的「听写」，或「听写训练 → 逐句听写」选文章。

- 有对轴时间就放原音片段，没有就朗读；语速在控制栏，重复次数在设置里
- 词槽提示每个词的长度；「提示」每点一次多露一个字母
- **整句模式**敲整句；**填空模式**只挖掉约三分之一的实词
- 词级对齐：漏词、多词、拼错、顺序颠倒、连写拆写、数字写法都能一词一对
- 整篇结算：逐句逐词着色，易错词汇总，重练错句、导出；结果进学习记录、计入热力图

快捷键：Enter 提交 · Ctrl 重播 · Ctrl+Shift 慢放 · Shift+Enter 提示 · Ctrl+← → 换句 · Esc 退出。

### 划线、笔记与生词词表

划到的内容自动整理进右侧笔记栏，点笔记里的词能跳回原文。同一个词在文章别处也显示划线（笔记里只记一条）。收藏单词 = 划线 + 进生词表；词库里没有的词也能收藏，会建一条只有词形的词条，之后用 AI 补全统一补释义。

**生词收进哪个词表**：两层，上层是文章所在的文件夹（同名词表），下层是这篇文章。书里的章节不单开词表，**跟着书走**：上层取书的文件夹，下层是书名那一个词表。没放进任何文件夹的才进「未分组生词」。也可以手动指定，书上指定的对整本书生效。旧版按章节开的词表、换过文件夹后还挂在旧位置的词表，打开词汇中心或阅读助手时自动搬过去，搬空的「未分组生词」会删掉。

侧栏「学习记录」把自己的笔记、章节笔记、AI 生成的文章、逐句听写结果、词族笔记汇到一处，每条都能改标题、改内容、删掉。整理文章之后，划线按原文重新定位。

## 学习与练习

### 打字

一轮完整流程：新词跟写 → 拼写 → 听写 → 默写，旧词自测 → 听写 → 默写。练习模式可在设置里换。

- 跟写和拼写按组交替（默认 7 个一组，可调）
- 单词卡下面一排：已掌握、笔记、收藏、跳过，都有快捷键
- 例句和短语里的词能点开查释义
- 练到一半退出会存断点，下次问「接着练」还是「重新开始」；重新开始也不丢成绩

### 配套教材

练习设置里把「每学 N 个新词插一次场景学习」设成非 0，这个词表就会有一套教材：**按话题分课**（一课 12~28 词）、**排学习顺序**、**逐段写课文**。某一课的词学完就端出那一段课文读，文中的词悬停出释义；一篇读完可以存进阅读助手，成为普通文章。教材没生成完不给开始学（学词顺序靠它），生成在右下角任务里跑，可停可续。另有造句训练：出问题的片段在原句里标红，错误类型跨会话累积。

### 听写检测与卡片

单词模式逐个来，列表模式一屏铺开统一判分，错词循环闭环；卡片消消乐把单词和释义打乱混排；卡片背单词翻卡评价认识程度，开着打字练习就要照着敲一遍才翻面。

## AI

### 配置

悬浮球 → 设置里填 API Key、Base URL（多数中转站要以 `/v1` 结尾）、模型。Key 存在浏览器 localStorage，不进仓库也不上传。

「长任务专用模型」：有些中转站按上下文窗口预扣费，百万上下文的模型一次请求就要预扣几百块、报 403。长任务在这里填个小窗口的便宜模型。「测额度」会连发一小一大两个请求，判断是请求太大还是账户门槛。

带思考过程的模型要 JSON 时处理分四层：请求里带关闭思考的参数 → 剥 `<think>` 标签 → 从 `reasoning_content` 里捞 JSON → 被截断就加大配额重试。即便如此，**非推理模型（如 `deepseek-chat`）跑结构化任务稳得多**。

### 哪些功能会调 AI

| 功能 | 在哪 |
|---|---|
| 整理文章 / 补译文 / 补英文 / 识别章节 / 学习笔记 | 阅读助手 |
| 试题题目翻译 | 阅读助手试题栏 |
| 跟读「难词」 | 影子跟读 |
| 配套教材、造句检查、播客稿 | 场景学习 |
| 单词补全、话题树梳理、词根梳理 | 设置页 |
| 词汇笔记「校对」 | 词汇宇宙右侧笔记 |
| AI 助手对话与操作 | 悬浮球 |

**不调用 AI 的**：音频对轴、录音与时长对比、词汇宇宙与本地分层、词汇笔记生成、试题解析与排版、分句分段、听写与测试、卡片、词典数据补全。

### AI 助手能动手

> 「建个词表叫雅思核心，把我刚查的词都加进去」 · 「给《每日听写 9-19》里划线的词补释义」 · 「每 30 分钟提醒我起来走走」

会改数据的操作一律先弹确认条，点了才执行，执行结果回填给模型，它不会编造「已经建好了」。支持：建词表、改名、加词、查词、按文章补词、定时提醒（设置 / 查看 / 取消）、跳页面、定位文章。定时提醒只在助手里管；某天要做的一次性事项建成待办。

## 数据与备份

刚 clone 下来是空的 —— `data/` 和 `resources/` 都不进仓库。

| 目录 | 装什么 | 能不能删 |
| --- | --- | --- |
| `resources/word_explanations/` | 词库原本，一个词一个 JSON | **不能**，原始资料 |
| `resources/articles/` | 阅读助手的文章 | 不能 |
| `resources/media/` | 文章关联的音频 | 不能，删了要重新导入 |
| `resources/word_index.json` | 分类索引 | 能，设置页一键重建 |
| `data/words.json` | 词库 + 学习状态的合并快照 | 能，设置页一键重建 |
| `data/` 下其余 | 词表、记忆卡片、活动日志、设置 | 不能，删了进度就没了 |

`data/words.json` 不只是缓存：词库文件里没有学习状态（认识程度、词条 id、加入时间、补全记账），它是两者的合并快照。重建时先把旧快照里属于用户的部分抠出来、重建完逐条贴回去。规矩是「所有信息以词库为准」：AI 补全、手工编辑都会同时写回 `resources/word_explanations/`。

存在浏览器 localStorage、不跟 `data/` 一起备份的：配套教材、色卡、界面偏好、两棵树的梳理结果。设置页「整体备份」导出词条、词表、记忆卡片、错词本、已掌握、学习设置、配色覆盖；换电脑后「恢复备份」读回来。

### 自定义配色

划线荧光笔和词汇宇宙共用一套色卡：可逐个改、删、加，能从图片取色，多套色卡可另存切换（内置默认 / 灰调 / 暖木）。先点色卡里的颜色，再点划线色或星系里任意分类就染过去。**笔记荧光色**是关系笔记的五支笔（派生、同根、近义、反义、二级词）。取色算法搬自作者的 MyLibrary 书架取色（72×72 采样 → 16 簇 → 10 轮 Lloyd 迭代 → 去近色），纯 canvas 实现。

## 桌面悬浮球与后台任务

用桌面方式启动时有悬浮球：点一下开对话框；长按调出播放操作台（只在有音频在放时才给）；播客在后台放着时，球上显示文章名和当前这句。

对轴、整理、梳理这些要跑几分钟的活儿登记在右下角任务面板：能看进度、能单独停止，三分钟没新进度会提示可能卡住。跑完或失败留一条等你点掉，失败写明原因。

## 开发

```bash
npm run dev                  # 开发服务器
npm run check                # 模板结构自检 + import 检查 + 界面规范检查
npm run build                # 模板自检通过才构建
npm run type-check           # vue-tsc
npm run test:unit            # vitest
npm run test:family          # 词汇笔记算法输出（模拟词库），改算法前后各跑一次对比
npm run test:family-regress  # 派生与词条提取回归，必须全过（Node 22.6+）
npm run test:paste-translation
npm run test:audio-pair
npm run family:check -- terrible export --topic 环境   # 用真实词库诊断（需先启动，Node 22.6+）
```

**界面规范**：返回、折叠、收藏、关闭、空状态、搜索框、弹窗等同类结构全项目只有一种写法，由 `src/components/ui/` 的公共组件与 `src/styles/tokens.css`、`ui.css` 提供；可管理列表统一用 `shared/core/useManageList.ts`。界面上不写说明文字，占位符只写名词，添加入口只用 ＋，这些由 `lint:ui` 检查；写死色值有基线，只许减少。全文见 [`docs/界面规范.md`](docs/界面规范.md)。

`build` 前置模板检查，是因为批量编辑很容易把 `v-else` 链打断，这类错只在构建时暴露。`check` 里的 import 检查找「调用了 `shared/core` 的函数、却没 import 也没本地定义」的地方 —— esbuild 会把没定义的名字当全局变量放过去，页面运行到那一行才白屏。

## 这个项目的来历

前身是我自己的 **VocabVerse** —— 一个只做词汇关系可视化的小工具，就是现在「词汇宇宙」这一块。用了一段时间发现光看关系图不够：能看出词之间的联系，但没有地方去练，也没有真实材料去用。

于是往两边扩：往下接了打字与听写，往上接了整本书导入与逐句对照。词库、配色、关系模型这些底子都是从 VocabVerse 带过来的。
