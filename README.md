# LanguageBridge

> 本地运行的英语学习工作台。词库、打字练习、3D 词汇关系图、阅读助手、听写检测在一个应用里，数据全部存在自己电脑上。

## 这是什么

市面上的背单词软件大多把"记住拼写"当终点。这个项目想解决的是另一件事：**一个词在你的词汇网络里处在什么位置**。

三条主线：

1. **词汇网络可视化** — 一万多个词按话题聚成星团，同根词、近义词、反义词是星团之间的连线。可以从「情感」钻到「积极情感」再钻到具体词族。
2. **对照真实材料学** — 导入整本书或资料，自动分章、中英逐句对照、划词入库、跟读对轴。
3. **练到能写出来** — 打字判定逻辑对照 [TypeWords](https://github.com/zyronon/typing-word) 实现，复习排期用 FSRS。

全程离线可用，只有 AI 补全那一步需要联网。

## 跑起来

需要 Node.js 18 以上。

**Windows 最省事**：双击 `LanguageBridge.vbs`。首次运行会在桌面建一个图标，之后从桌面点就行，不弹命令行窗口。

**命令行**：

```bash
npm install
npm start          # 等同 node scripts/server.mjs
```

首次启动会自动装依赖并构建，之后只在源码真的变过时才重新构建。浏览器会自己打开 `http://127.0.0.1:58712`。

已经在跑的时候再点一次启动器，不会开出第二个服务，而是把浏览器指到已有的那个。端口被占会自动往上找一个空的，并把新端口写回 `port.txt`。

### 可选：后端

`backend/` 是一个 FastAPI 服务，把词条、文章、学习记录落到磁盘文件，作为浏览器 IndexedDB 之外的第二份存储。不启动也能用，但浏览器数据被清掉就没有兜底了。

```bash
cd backend
pip install -r requirements.txt
python main.py
```

### 打包成 exe 发给别人

双击 `一键打包EXE.bat`。产物在 `dist-exe\`，整个文件夹拷给别人即可，对方不用装 Node。

词库放在 exe 旁边而不是塞进 exe，因为 pkg 打进去的是只读快照，而 AI 补全、收生词、改标签都要往词库里写。

## 功能

| 模块 | 做什么 |
| --- | --- |
| **词汇中心** | 考试 / 话题 / 词根词缀三个维度并行叠加，再叠一层认识 / 模糊 / 不认识 |
| **词汇宇宙** | 3D 力导向关系图，四类关系连线，大类 → 话题 → 词族逐级钻取 |
| **学习 / 打字** | 逐字符实时判定、跟写 / 拼写 / 自测多种练习类型，FSRS 排期 |
| **阅读助手** | 导入整本书自动分章，逐句对照、划词入库、朗读、复述批改 |
| **听写检测** | 单词模式逐个来，列表模式一屏铺开统一判分，错词循环闭环 |
| **场景学习** | 按话题生成成套教材与实战批改 |

### 词汇宇宙

按「核心词做恒星」组织：每个词族只画核心词，衍生词跟着核心词归入所在星团。这样分类不会被衍生词污染（`aggressiveness` 不会因为词族关系被拖进「积极情感」），节点数也从五千多降到几百，力学模拟顺畅。

三层钻取：大类星团（情感 / 科技 / 自然与环境…）→ 话题星云（积极情感 / 消极情感）→ 词族。每一层悬停时整团亮起，点击飞进下一层，面包屑可以点回任意一级。

按掌握程度上色时亮度来自记忆曲线：学熟了亮，长期不复习自己暗下去。

### 长文与整本书

导入一本书时，分章和翻译是分开的两步：

1. **结构** — 优先用文件自身的标题层级（`##`、编号题目）。识别不出来时才让 AI 判断「哪几行是章节标题」，只回行号，逐条用原文校验，编造的行号直接丢弃。
2. **正文** — 中英配对、断句全部由本地代码做，确定性的，不经过模型。
3. **补译** — 只把缺译文的句子送去翻译，每批 20 条、可断点续跑。章节号这类结构行原样保留，不浪费一次请求。

三种输入都能处理：中英对照（段内配对，中英顺序不限）、纯英文、纯中文（按中文标点断句，英文栏留空等翻译）。

### 影子跟读

给文章配音频后逐句跟读。三条路拿到「每句从第几秒到第几秒」：

1. **导入字幕**（`.srt` / `.vtt`）— 最准最快
2. **拖入视频** — 本机 `ffmpeg` 抽音轨，原视频不保存
3. **自动转写** — 本机跑 whisper，音频不出这台电脑

对轴之后可以连续播放：读到哪句高亮哪句、自动滚动，可调速度、单句循环、句间停顿。

## 数据放在哪

刚 clone 下来是空的 —— `data/` 和 `resources/` 都不进仓库，它们是使用者自己的资料。

| 目录 | 装什么 | 能不能删 |
| --- | --- | --- |
| `resources/word_explanations/` | 词库原本，一个词一个 JSON | **不能**，这是原始资料 |
| `resources/articles/` | 阅读助手的文章 | 不能 |
| `resources/word_index.json` | 分类索引，从词库扫出来的 | 能，设置页一键重建 |
| `data/words.json` | 工作缓存，为了启动读一个文件而不是一万多个 | 能，设置页一键重建 |
| `data/` 下其余 | 学习状态：词表、记忆卡片、活动日志、设置 | 不能，删了进度就没了 |

一句话：**`resources/` 是原本，`data/words.json` 是可再生的缓存，`data/` 下其余是学习记录。**

### 备份

设置页「整体备份」导出一个文件，含词条、词表、记忆卡片、错词本、已掌握、学习设置、配色覆盖。换电脑之后「恢复备份」读回来。

浏览器里那份只是缓存。启动了后端的话，阅读助手里「从后端恢复」可以在浏览器数据被清掉之后把文章拉回来。

## AI 补全

词库原本里没有话题和词根词缀这两项，需要模型补一次。设置页「AI 补全」，用右下角 AI 面板里配好的连接（key 存在浏览器 localStorage，不进仓库也不上传）。

跑法是先扫一遍看每个词缺什么，按「缺的是同一组东西」归堆再切批，所以提示词只问这批真缺的项；每批立刻落盘，中断了下次从断点接着走。考纲标签不问模型 —— 词库 JSON 里本来就有，设置页有免费的回填。

## 技术栈

Vue 3 + TypeScript + Vite + Pinia，3D 图用 [3d-force-graph](https://github.com/vasturiano/3d-force-graph) / three.js，本地存储 IndexedDB（idb），可选后端 FastAPI。

```
apps/
  word-core/           词汇中心与关系图组件
  study/               学习、打字、主页
  dictation-app/       听写检测
  reading-assistant/   阅读助手
shared/
  core/                切分、判定、调度、数据库等无 UI 逻辑
  stores/              Pinia
backend/               可选的 FastAPI 落盘服务
scripts/               启动器、构建、模板自检
```

## 开发

```bash
npm run dev          # 开发服务器
npm run check        # 模板结构自检：标签配对、v-if 链完整性
npm run build        # 自检通过才构建
npm run type-check   # vue-tsc
npm run test:unit    # vitest
```

`npm run build` 前置了模板检查，是因为批量编辑很容易把 `v-else` 链打断或者删掉正在被调用的函数，而这类错只在构建时才暴露。
